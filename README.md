# Ali Khan — Portfolio

Personal portfolio for **Ali Khan**, Junior Software Engineer and Co-Founder at
[Webistic Marketing Solutions](https://webistic.co/).

Built with Next.js (App Router), React 19, Tailwind CSS and Heroicons, and
exported as a fully static site.

## Stack

| Layer | Choice |
| --- | --- |
| Framework | Next.js 15 (App Router, ISR for the blog) |
| UI runtime | React 19 |
| Styling | Tailwind CSS + a small in-repo component kit (`src/components/ui`) |
| CMS | Sanity (project `utmnj4rd`) — content fetched at request time |
| Icons | Heroicons |
| Font | Roboto via `next/font` |
| Hosting | Vercel (or any static host) |

There is no third-party component library: `src/components/ui` contains the four
primitives the site needs — `Typography`, `Card`/`CardBody`, `Button` and
`IconButton` — built directly on Tailwind, with class merging via
`tailwind-merge` so call sites can override styles safely.

## Getting started

```bash
npm install
npm run dev      # http://localhost:3000
```

Other scripts:

```bash
npm run build      # static export into out/
npm run preview    # serve the exported site locally
npm run lint       # ESLint
npm run typecheck  # tsc --noEmit
```

## Customizing

**All personal details live in [src/lib/site.ts](src/lib/site.ts)** — name, role,
company, email, WhatsApp, LinkedIn, photo filename, description and keywords.
Change them there once and the hero, contact section, footer, metadata, JSON-LD
and sitemap all follow.

### Portrait

Drop your photo at `public/ali-khan.jpg`. The hero shows it automatically and
falls back to an "AK" monogram if the file is missing.

The full-resolution master lives in `assets/ali-khan-original.jpg` (2048×2048).
The copy served from `public/` is resized to 1300×1300 and compressed, which
takes the hero image from 2.7 MB to ~146 KB.

### Resume PDF

Put your CV at `public/Ali_Khan_Resume.pdf`. The **Download Resume** button in
the resume section appears automatically on the next build and saves the file as
`Ali_Khan_Resume.pdf`. While the PDF is missing the button is omitted entirely,
so the site never ships a link to a 404.

The filename is enforced twice: the anchor carries `download="Ali_Khan_Resume.pdf"`
and [vercel.json](vercel.json) sends `Content-Disposition: attachment;
filename="Ali_Khan_Resume.pdf"`, so the name survives browsers that prefer the
response header over the HTML attribute.

### Brand assets

`public/favicon.png` and `public/og-image.png` are generated by:

### Contact form

The form has no backend: on submit it opens WhatsApp (app on mobile, WhatsApp Web
on desktop) with the visitor's name and message pre-filled, so it works on a
static host with no service and no API keys. The number comes from
`SITE.whatsappUrl` in [src/lib/site.ts](src/lib/site.ts). To send messages
server-side instead, swap `handleSubmit` in
[src/app/contact-form.tsx](src/app/contact-form.tsx) for a Formspree, Resend or
Vercel Function endpoint.

## Environment variables

Copy [.env.example](.env.example) to `.env` and adjust:

| Variable | Purpose |
| --- | --- |
| `NEXT_PUBLIC_SITE_URL` | Canonical origin for metadata, sitemap and robots. Defaults to `http://localhost:3000`. |
| `NEXT_PUBLIC_BASE_PATH` | Sub-path hosting only, e.g. `/my-repo` for GitHub Pages. Leave empty on Vercel. |
| `NEXT_PUBLIC_SANITY_PROJECT_ID` | Defaults to `utmnj4rd`, so no setup is needed. |
| `NEXT_PUBLIC_SANITY_DATASET` | Defaults to `production`. |
| `SANITY_API_READ_TOKEN` | Only for a private dataset. Leave empty for public content. |

## Blog (Sanity)

Posts live in Sanity (project `utmnj4rd`, dataset `production`) and are written
through Sanity Studio.

**Hosted Studio:** <https://ali-khan-portfolio.sanity.studio>

Open that URL, sign in with the Sanity account that owns the project, pick the
**production** dataset and the **Post** content type. Create a post (title, slug,
excerpt, publish date, optional cover image, body) and press **Publish** — no
commands, no deploy.

The Studio source is in [studio/](studio). To run or redeploy it from a terminal:

```bash
cd studio
npm install
npm run dev      # local studio at http://localhost:3333
npm run deploy   # republish https://ali-khan-portfolio.sanity.studio
```

The schema is [studio/schemas/post.ts](studio/schemas/post.ts) — its field names
must stay in sync with the GROQ queries in [src/lib/blog.ts](src/lib/blog.ts).

**Publishing.** The blog uses ISR with a 60-second window: a new or edited post
appears on the live site within a minute of publishing, with no redeploy. The
first request after that window regenerates the page.

**Without content**, `/blog` renders an empty state and the site still builds and
deploys normally — the dataset can be empty.

## Deployment

### Vercel

Import the repository and deploy — no configuration needed. The blog is served
with ISR, so the project must build as a normal Next.js app (the default).

Set `NEXT_PUBLIC_SITE_URL` to the final domain once it is assigned.

### GitHub Pages

GitHub Pages can only serve static files, so the deploy script switches the
build to `output: "export"`:

```bash
node scripts/gh-deploy.mjs
```

⚠️ Static mode requires **at least one published post** — Next.js refuses to
export a dynamic route that prerenders nothing, so `STATIC_EXPORT=1` fails on an
empty dataset. GitHub Pages also loses on-demand revalidation: new posts need a
redeploy.

It builds with `NEXT_PUBLIC_BASE_PATH=/<repo>`, writes `out/.nojekyll` (GitHub
Pages would otherwise strip `_next/`) and publishes `out/` to the `gh-pages`
branch. Override the sub-path with `GH_PAGES_BASE_PATH` if the folder name and
the repository name differ.

## Project layout

```
src/app/            page sections (one file per section)
src/app/blog/       blog index and post pages
src/components/     navbar, footer, cards
src/components/ui   Tailwind primitives: Typography, Card, Button, IconButton
src/lib/site.ts     personal details and deployment settings
src/lib/sanity.ts   Sanity client and image URLs
src/lib/blog.ts     GROQ queries and post types
studio/             Sanity Studio (separate app, own package.json)
public/             favicon, OG image, portrait, resume
scripts/            brand asset generation, GitHub Pages deploy
```

The Tailwind breakpoints in [tailwind.config.ts](tailwind.config.ts) are
deliberately set to 540/720/960/1140/1320px — the scale the layout was designed
on. Changing them will reflow every section.
